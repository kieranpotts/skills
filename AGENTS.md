# Skills

The capitalized words REQUIRED, MUST, MUST NOT, RECOMMENDED, SHOULD,
SHOULD NOT, OPTIONAL, and MAY are to be interpreted as described in
[IETF RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

## Project overview

This is a curated collection of agent skills for AI-assisted and agentic
software development. The skills encode established development practices —
SDLC phases, version control conventions — into reliable prompts. These
prompts are designed to produce consistent, predictable outputs across
mainstream coding models.

Each skill is portable and independent. No skill hands off to another skill.
You can install or delete any one skill on its own, and orchestrate them
into all sorts of workflows.

Every `SKILL.md` file SHOULD be token-efficient (RECOMMENDED limit: 300 lines)
and MUST pass the validator checks — described below.

## Tech stack

- Bash (installer and validator scripts).

- `pre-commit` (Python) for Git hooks.

- `skills-ref` (Python, OPTIONAL) for canonical `SKILL.md` validation.

- GitHub Actions for CI.

## Project structure

- **`skills/`**
  One subdirectory per skill, each containing a `SKILL.md` (for agents)
  and a `README.md` (for humans).

- **`skills/create-skill/`**
  Use this to author new skills, both in this repository and in downstream
  projects. It bundles the canonical template (`assets/skill-template/`),
  the validator (`scripts/`), and reference docs (`references/`).

- **`build/`**
  Compiled agent-specific artifacts generated by `./run/install`. Do not
  edit directly.

- **`run/`**
  Dev tools. Just the `install` script, for now.

- **`docs/`**
  Documentation for human maintainers and contributors.

- **`skills.sh.json`**
  Controls how skills in this collection are presented on the
  [skills.sh](https://www.skills.sh/) website.

- **`CHANGELOG.md`** Version history.

- **`CONTRIBUTING.md`** For humans only.

## Tools

- **`./run/install --help`** to build and install skills into supported agents.

- **`./skills/create-skill/scripts/validate.sh <skill_dir>`** to validate
  a skill directory before committing.

- **`pre-commit run --all-files`** for linting commit messages
  (requires `pipx install pre-commit && pre-commit install`).

## Rules

- MUST follow the [`branch`](./skills/branch/SKILL.md) skill for all
  branch names.

- MUST follow the [`commit`](./skills/commit/SKILL.md) skill for all
  commit messages.

- MUST run the validator on any new or modified skill before committing.

- To add or improve a skill, MUST use the
  [`create-skill`](./skills/create-skill/SKILL.md) skill. See also
  [`docs/creating-skills.md`](./docs/creating-skills.md).

- `SKILL.md` files SHOULD NOT exceed 300 lines.

- Each skill directory MUST contain a sibling `README.md`.

- A skill's `README.md` is for humans. It MUST include usage docs (for
  users to invoke a skill directly). It MAY include reference material that
  provides background to a skill's design rationale, or other information
  that will not be relevant to agents.

- Each `SKILL.md` MUST include one of `## Instructions` or `## Rules`, or both.

- Each `SKILL.md` MUST also include `## Success criteria`.

- Each `SKILL.md` MUST include a `## Interface` section that clearly defines
  the input and output expected of the agent, plus instructions whether
  the agent should prompt the user for more input (interactive mode).

- A `SKILL.md`'s `## References` section, if present, MAY point to a mix of
  both internal and external references resources — the skill's own bundled
  assets plus assets that must be fetched via a web request.

- Each skill MUST have a single responsibility. It does one job and stops
  at its boundary. It leaves adjacent work to the caller. For example, a
  proofreading skill edits prose but does not commit the change.

- Skills MUST be portable and independent, with no hand-offs to other skills.

- MUST NOT commit anything under `build/`. It is gitignored. Only
  `build/README.md` is tracked.
