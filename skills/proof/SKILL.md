# Proof

Proofread the AsciiDoc files in this repository, opening one pull request per topic.

This is a fully agentic workflow. It does not require user interaction, except to confirm destructive operations. The user approves proofreading changes asynchronously via the pull requests generated by this skill.

##  Instructions

1.  **Extract targets from the OPTIONAL `topic` argument.**

    Process `$ARGUMENTS`. If a `topic` is given, the topic list is just that one directory. Otherwise, the topic list is every immediate sub-directory under `./src/` (`aws`, `bash`, `debian`, etc.).

    Pick the first topic and proceed to step 2.

2.  **Verify the target topic.**

    The target MUST be a sub-directory under `./src/`, eg. `./src/go`. Verify the directory exists and contains at least one AsciiDoc file (a plain text file with the `.adoc` extension). If the directory is invalid or has no source files in it, skip it and jump to step 10.

    Otherwise, build the list of `.adoc` files within the topic directory (and its sub-directories) and proceed to step 3.

3.  **Proofread each file in the topic and apply edits in place.**

    Work through the files one at a time. For each file, apply your proofreading edits per the rules below, then drop the file's context from your working memory before opening the next file.

    Track which files you actually edited.

    When all files in the topic have been processed: if you edited at least one file, proceed to step 4; if not, proceed to step 10.

4.  **Create a fresh branch from the `dev` trunk.**

    Branch naming convention: `temp/proof-<topic>` where `<topic>` is the topic directory name, eg. `temp/proof-aws`.

5.  **Commit the edited files.**

    Commit message convention: `proof: <topic>`, eg. `proof: aws`.

    Stage only the files you edited: `git add <file1> <file2> …`.

6.  **Push.**

    `git push -u origin <branch>`

7.  **Open a PR.**

    ```
    gh pr create --base <trunk> --head <branch> \
      --title "proof: <topic>" \
      --body "<details>"
    ```

    Replace `<details>` with a bullet list grouped by file, summarising the discrete changes you made in each.

8.  **Print a summary to the terminal.**

    Topic, branch, and PR URL.

9.  **Return to the trunk branch.**

    `git switch dev`

10. **Pick the next topic.**

    If there are more topics in the list, pick the next one and continue from step 2. Else finish.

## Rules

-   **MUST write in American English.**

-   **MUST write valid AsciiDoc syntax.**

-   **MUST NOT change contents of any code blocks or `inline code`.**

-   **MUST work through one file at a time within a topic.**

    Finish proofreading each file before opening the next. After you finish a file, do not re-read it, and remove its context from your context window.

    Only after every file in the topic is done do you commit and open the PR.

-   **MUST pause and ask me before doing anything destructive.**
